Для отображения карты нужен бесплатный ключ JS API. Получите его в Кабинете разработчика Яндекса (раздел «JavaScript API и HTTP Геокодер»). При создании ключа заполните поле «Ограничение по HTTP Referer» — впишите localhost, если открываете файл через локальный сервер (подробности — README.md, раздел «Как открыть карту»).

Ключ сохраняется только в localStorage вашего браузера и никуда не отправляется, кроме api-maps.yandex.ru.

Подробно о карте

Полное объяснение каждого элемента: что вы видите, как это работает и почему сделано именно так

1. История исследования — зачем вообще сравнивались системы координат

Исходная задача звучала так: файл DT_Task2_Voykovskiy.geojson (2723 объекта Войковского района) заявлен в системе CRS84 (WGS84 с порядком осей «долгота, широта»). Нужно было понять — действительно ли он корректен в этой системе, или для точного показа на Яндекс Картах его сначала нужно перевести в местную систему МСК-77 и лишь затем обратно в WGS84 для отображения. Предположение «это Москва → наверняка МСК-77» специально не принималось на веру — требовалось доказательство измерениями.

Проверка шла в несколько этапов: (1) валидация исходного файла — диапазоны координат, самопересечения геометрии; (2) изучение официальной документации Яндекс Карт — в каком порядке и в какой системе она принимает координаты; (3) построение обоих вариантов данных с полностью задокументированными параметрами перехода; (4) численные тесты преобразования на выборке объектов; (5) сверка с живой картой Яндекса через браузер.

Итог: исходный файл — подлинный WGS84/CRS84. Это подтверждено независимо — через геодезический пересчёт площади каждого объекта по координатам, который совпал с паспортной площадью с медианным отклонением 0.001%. Переводить в МСК-77 для показа на Яндекс Картах не нужно.

Полная версия — в файлах DT_Task2_Voykovskiy_report.pdf и README.md, которые идут вместе с этой картой.

2. Как читать карту — режимы «Шторка» и «Наложение»

Шторка (режим по умолчанию) — два экземпляра карты показаны рядом, разделены подвижной границей. Слева — слой WGS84 (исходные координаты), справа — слой МСК-77, пересчитанный обратно в WGS84. Оба всегда показывают одну и ту же точку и масштаб — карты синхронизированы: подвиньте/увеличьте одну, вторая повторит движение.

Границу можно двигать мышью или пальцем на сенсорном экране. С клавиатуры: наведите фокус на границу (клавиша Tab) и используйте стрелки ← / → — так делали, чтобы управление было доступно и без мыши.

Наложение — обе версии рисуются друг поверх друга на одной карте. В сайдбаре слева включайте/выключайте слои галочками и меняйте их прозрачность ползунками — так удобнее ловить мелкие расхождения: например, сделайте один слой полупрозрачным и посмотрите, проступают ли контуры другого слоя из-под него.

Поскольку WGS84 и МСК-77→WGS84 отличаются на доли миллиметра, в обоих режимах они выглядят как один слой — так и должно быть.

3. Слои и цвета — что означает каждый
Синий — WGS84 (исходный)

Координаты ровно такие, как в файле DT_Task2_Voykovskiy.geojson, без какого-либо преобразования. Это рекомендованный вариант для Яндекс Карт.

Зелёный — МСК-77 → WGS84 (обратное преобразование)

Тот же объект: сначала пересчитан в метровую систему МСК-77 (эллипсоид Бесселя, проекция Гаусса-Крюгера, официальные параметры 7-параметрического преобразования Хельмерта), затем пересчитан обратно в WGS84. Если бы в преобразовании была ошибка (перепутанные оси, не та зона, неверный знак параметров), этот слой отъехал бы от синего на метры — сдвига не произошло.

Оранжевый — диагностика несогласованности реализаций

Это единственный слой, который намеренно построен с ошибкой — в учебных целях. В открытых источниках нашлось два слегка разных набора параметров МСК-77 (отличаются началом координат на 21.67 м). Этот слой получен, если пересчитать объект в одну реализацию, а обратно — по параметрам другой. Он показывает, как выглядела бы настоящая ошибка привязки на карте — чтобы было с чем сравнивать «идеальное» совпадение синего и зелёного слоёв. Он не описывает реальное состояние исходных данных.

4. Контрольные участки (13) — зачем именно эти точки

Чтобы проверка не ограничивалась «на глаз в центре района», отобраны 13 показательных объектов:

  • Центр района — типичная точка, ближе всего к среднему по всем координатам.
  • Крайние точки — север, юг, восток, запад: проверяют, не «плывёт» ли преобразование по краям района.
  • Диагональные направления — СВ, СЗ, ЮВ, ЮЗ: дополнительное покрытие площади района.
  • Минимальный, медианный и максимальный по площади объект — проверка на разных масштабах, от маленького сарая до крупного строения.
  • Объект с самопересечением геометрии — реальный пример дефекта исходных данных (таких 143 из 2723, все — некритичные «шпоры», не искажающие форму).

Клик по любой карточке в сайдбаре переносит обе карты (в режиме «Шторка») к этой точке с увеличением. Оранжевая цифра на карточке — это то самое смещение 21.67 м из диагностического слоя (см. пункт 3) — оно одинаковое для всех точек, так как это постоянный сдвиг начала координат, а не случайная ошибка.

5. Что уже проверено вживую на Яндекс Картах

Часть контрольных точек была сверена напрямую через браузер на yandex.ru/maps:

  • Центр района — поиск по координатам вернул тот же адрес и те же координаты (совпадение до 6-го знака): «4-й Новоподмосковный переулок, 3с2».
  • Самый крупный объект (598.6 м²) — попал на реальную мощёную площадку/парковку; линейкой Яндекс Карт подтверждён масштаб (замер ≈24.9 м совпал с ожидаемой стороной полигона).
  • Крайняя северная точка — поиск вернул «Головинское шоссе» — именно ту улицу, по которой проходит официальная граница района.
  • Крайняя южная точка — на спутниковом снимке рядом видна железная дорога, совпадающая с описанием южной границы района из независимого источника (mosopen.ru).

Это проверка правдоподобия (все точки — в реальных, осмысленных местах), а не измерение расхождения в сантиметрах по каждому углу здания — для точного покадрового сравнения нужен API-ключ и именно этот инструмент, запущенный с реальными тайлами (что вы сейчас и делаете).

6. Что не проверено / ограничения
  • Точное значение «ложных смещений» официальной МСК-77 (0 м или 16.1/14.5 м) подтверждено из вторичных источников, не из первоисточника напрямую — расхождение между ними и даёт те самые 21.67 м из диагностического слоя.
  • Официальные ортофотопланы Москвы (Росреестр/ИАИС ОГД) не использовались — сверка шла по спутниковым снимкам потребительской карты Яндекса.
  • Пиксельно-точный оверлей контур-в-контур выполнен для всех 2723 объектов в этом инструменте, но количественная сверка «на сколько сантиметров смещён именно этот угол здания» вручную не проводилась для каждого объекта.

Полный список — в отчёте, раздел «Что требует уточнения».

7. Про ключ API и приватность

Ключ, который вы ввели при открытии карты, хранится только в localStorage вашего браузера и отправляется исключительно на api-maps.yandex.ru — никуда больше. Если эта страница размещена по публичной ссылке (например, на GitHub Pages), помните: геометрия всех 2723 объектов района становится доступна любому, у кого есть ссылка на страницу.
